# 🍏 GreenStep
 
도착하면 딱, 초록불
 
신호등 앞에 도착했는데 빨간불이라 멍하니 기다리거나, 깜빡이는 초록불을 보고 뛰어본 적 있나요? GreenStep은 내가 횡단보도에 도착하는 순간 **초록불로 딱 바뀌도록** 걷는 속도를 맞춰주는 모바일 웹앱입니다.
 
현재 위치, 나의 보행 속도, 서울시 실시간 신호 정보를 비교해서 "조금 천천히 걸어도 돼요"처럼 지금 어떻게 걸으면 되는지 알려줍니다. 기다리지도, 뛰지도 않고 걷던 그대로 건너는 게 목표예요. 이번 신호에 맞추려면 뛰어야 하는 상황이라면 무리하지 말고 다음 신호를 기다리라고 안내합니다.
 
신호 상태는 사과로 보여줍니다. 🍏 초록사과는 건너도 됨, 한 입 베어 문 깜빡사과는 점멸, 🍎 빨간사과는 대기, ❔ 모르는사과는 신호 정보 없음입니다.
 
## 🛠 기술 스택
 
React TypeScript Vite TailwindCSS Vercel
 
| 분야 | 스택 |
| --- | --- |
| Frontend | React, Vite, TypeScript, Tailwind CSS |
| 지도 / 위치 | Kakao Maps JavaScript SDK, Geolocation API |
| Backend | Vercel Serverless Function (신호 API 프록시) |
| External API | 서울 T Data C-ITS 신호제어기 신호 잔여시간 정보, 교차로 Map 정보 |
| Test | Vitest |

## 🚀 실행 방법
 
저장소 클론
 
```bash
git clone [저장소 URL]
cd greenstep
```
 
패키지 설치
 
```bash
npm install
```
 
환경변수 설정
 
- 프로젝트 루트에 `.env` 파일 생성
- `.env.example` 참고해서 값 채우기 (팀 내부 공유)
  - `VITE_KAKAO_JS_KEY`: Kakao JavaScript 키 (Kakao Developers에 `http://localhost:5173` 도메인 등록 필요)
  - `VITE_DATA_MODE`: `mock` / `replay` / `live`
  - `TDATA_API_KEY`: 서울 T Data 인증키. 브라우저에 노출되면 안 되므로 `VITE_`를 붙이지 않음
개발 서버 실행
 
```bash
npm run dev       # 화면만 개발할 때 (mock 신호)
npx vercel dev    # 실제 신호 API까지 쓸 때 (Vercel Function 포함)
```
 
→ http://localhost:5173 접속
 
- `npm run dev`만 띄우면 `/api/signal`이 없어서 실시간 신호를 못 받는다. live 모드로 확인하려면 `vercel dev`로 띄우기
- 주소 끝에 `?demo=1`을 붙이면 데모 패널이 열린다 (가짜 신호, 가상 걷기, 신호 강제 전환)
- 횡단보도는 `src/data/crosswalks.json`에서 관리한다. 현장에서 실제 신호와 맞는지 확인하기 전까지는 `verified: false`로 두고, 이 상태면 실시간 예측을 하지 않는다
요구 사항
 
- Node.js 18 이상
- Vercel CLI 전역 설치 (`npm install -g vercel`), `vercel login` 완료

## 메인 화면 지도

MapLibre와 OpenFreeMap의 전 세계 벡터 타일로 현재 위치 주변의 실제 도로를 흑백 블록 스타일로 표시합니다.
건물 윤곽은 생략하고 도로 사이를 하나의 빈 블록으로 표시합니다. 지명·장소명·도로명은 한국어 이름을 우선 표시하며, 한국어가 없으면 현지 이름을 표시합니다. 확대하면 장소명도 나타나고 겹치는 글자는 자동으로 생략합니다. 카카오 키는 이 지도에 필요하지 않습니다.

- 첫 진입 시 위치 권한을 요청하고 `watchPosition`으로 받은 GPS 위치에 지도를 맞춥니다. 특정 지역 범위 제한이 없습니다.
- 지도에 내 위치를 졸라맨으로 표시합니다. 직접 지도를 드래그하면 자동 중심 이동을 멈추고, ‘내 위치’를 누르면 다시 따라갑니다.
- 위치 거부·오류 시 권한 설정 안내와 재시도를 제공하며, 사용자가 기본 위치를 선택하면 동덕여대 주변을 표시합니다.
- 도로 타일은 인터넷 연결이 필요합니다. 지도 로드 실패 시 재시도할 수 있습니다. WebGL을 지원하는 브라우저가 필요합니다.
- 현재 지도 중심 약 450m 주변의 OpenStreetMap 횡단보도를 조회해 등록 데이터와 합칩니다. 현재 위치 기준 가까운 횡단보도를 지도에는 최대 5곳, 목록에는 최대 3곳 표시합니다. 지도에는 해당 5곳의 줄무늬와 사과를 표시합니다. 사과 선택 시 `/crosswalk/:id`로 이동합니다.
- 신호가 없거나 미확인인 횡단보도는 모르는 사과로 표시합니다. 현재 횡단보도 좌표는 미등록 상태입니다.

지도 제공: [OpenFreeMap](https://openfreemap.org/quick_start/), © OpenMapTiles, © OpenStreetMap contributors.
기존 카카오 지도 컴포넌트는 유지하지만 메인 화면에서는 사용하지 않습니다.
테스트: `node --test tests/*.test.mjs` (Node.js 22.18 이상).


## 신호 API 연동 (#7)

- `/api/signal?itstId=교차로ID&direction=방향`은 서버의 `TDATA_API_KEY`로 T Data를 호출합니다.
- 키 이름에 `VITE_`를 붙이지 않으며, `.env.local`이나 키 값을 커밋하지 않습니다.
- 로컬은 키가 설정된 동일한 터미널에서 `npx vercel dev`를 실행합니다. Windows에서 심볼릭 링크 권한 오류가 나면 관리자 PowerShell을 사용합니다.
- Vercel 배포 시 프로젝트 환경변수에 `TDATA_API_KEY`를 추가하고 사용할 Preview/Production 환경을 선택한 뒤 새로 배포합니다. 로컬 PowerShell 환경변수는 배포 서버로 전달되지 않습니다.
- 메인 화면의 데이터 모드에서 실시간을 선택하면, `verified: true`이며 `signalIntersectionId`와 `signalDirection`이 유효한 항목만 조회합니다.
- 조회 완료 후 10초 간격으로 갱신하며 같은 교차로·방향은 한 번만 요청합니다. 실제 이용 전 발급받은 API 호출 한도에 맞춰 간격을 조정해야 합니다.
- 화면 이동과 모드 전환 시 요청을 취소합니다. 실패 시 이전 신호를 재사용하지 않습니다.
- 정보 경과 10~30초는 지연, 30초 초과는 사용 불가입니다. 잔여시간 만료 시 다음 신호를 추측하지 않고 UNKNOWN으로 전환합니다.
- mock의 안내 시나리오는 live 화면에 적용하지 않습니다. replay는 준비 중 안내를 표시합니다.
- `/signal-test`는 교차로 20386의 ne 보행 신호를 수동 조회하는 개발용 화면이며, 실제 등록 횡단보도의 검증을 대체하지 않습니다.
- 현재 등록된 3곳은 위치·신호 매핑 미확인 상태입니다. 값을 임의로 채우거나 verified를 true로 변경하지 않습니다.
- 점멸 상태의 서울 API 매핑과 실제 횡단보도 신호 대응 관계는 아직 확인이 필요합니다. 서울 전체 횡단보도 검색은 이 작업에 포함되지 않습니다.
- 검사: `npm run build`, `npm run lint`, `node --test tests/*.test.mjs`


## 데모 모드

`/crosswalk/main-gate?demo=1`에서 데모 패널을 사용할 수 있습니다.
미확인 횡단보도도 데모에서는 시연할 수 있으며, 실제 신호와 구분되는 시뮬레이션 표시가 나옵니다.
일반 상세 화면의 미확인 횡단보도 제한은 유지합니다.

- `mock`: 빨강 23초 → 초록 50초 → 점멸 6초로 순환하는 생성 신호입니다.
- `replay`: 초록 12초 → 점멸 6초 → 빨강 30초 → 초록 40초의 시연 타임라인을 반복합니다. 실제 관측 기록이 아닌 fixture입니다.
- `live`: `/api/signal?crosswalkId=...&controllerId=...`에서 3초 간격으로 신호를 조회합니다. 현장 확인과 제어기 등록이 필요합니다. API 미구현·실패·오래된 데이터는 모르는 사과로 처리하고 생성 신호로 대체하지 않습니다.
- 가상 걷기: 목표 60m 전방에서 선택 속도로 이동합니다. 횡단보도 앞에서 초록 신호와 충분한 시간을 기다린 뒤 가상 횡단을 마치면 결과 화면으로 이동합니다. 좌표가 없는 경우 정문 주변의 가상 좌표를 쓰며 실제 위치로 취급하지 않습니다.
- 가상 속도 슬라이더: 이동량·도착 예상 시간·횡단 가능 시간 계산에 즉시 반영됩니다. 실제 GPS 모드에서는 슬라이더를 비활성화하고 GPS 좌표 변화로 속도를 추정합니다.
- 강제 신호: 선택 신호부터 새 타이머로 순환합니다. 해제하면 원래 mock/replay/live 흐름으로 복귀합니다. live에서도 강제 신호는 시뮬레이션으로 표시합니다.
- 처음부터 다시 걷기: 가상 위치·경과시간·신호 타이머·강제 신호를 초기화합니다. 선택 속도와 데이터/GPS 모드는 유지합니다. 모드를 바꿔도 새 세션을 시작하며 이전 타이머·요청은 정리합니다.

신호 API의 프론트엔드 응답 계약은 다음과 같습니다. `updatedAt`은 실제 관측 시각의 Unix 밀리초 값입니다.

```json
{ "signal": "GREEN", "remainSec": 40, "updatedAt": 1794211200000 }
```

`signal`은 `GREEN`, `FLASHING`, `RED`, `UNKNOWN` 중 하나입니다. `UNKNOWN`은 `remainSec`을 생략할 수 있습니다.
10초 이상 지난 정보로는 예측하지 않으며, 30초 초과 또는 잔여시간 만료 시 UNKNOWN으로 처리합니다.
현재 저장소에는 실제 신호 API가 없으므로 live 수신 확인은 API와 제어기 데이터 연동 후 진행해야 합니다.


## 걷기 결과 기록

`/result`는 마지막 완료 세션의 걸린 시간·평균 속도·뛴 횟수를 표시합니다. 피그마의 고정값은 사용하지 않습니다.
평균 속도는 총 이동 거리 / 전체 경과시간이며, 신호 대기 시간도 포함합니다.

- 실제 GPS: 상세 화면에서 처음 유효한 위치를 받은 시점부터 기록합니다. 확인된 횡단보도 좌표의 10m 이내에서 ‘횡단 기록 시작’을 누릅니다. 시작 이후 이동 거리가 등록 횡단 길이(0.2m 허용 오차) 이상이고, 시작점으로부터 순이동도 길이의 80% 이상일 때 ‘안전하게 건너기 완료’를 눌러 결과로 이동합니다. 마지막 GPS가 10초 이상 오래되면 완료할 수 없습니다. 횡단 방향/종점 좌표가 없어 자동 완료 대신 사용자 확인을 함께 사용합니다.
- 현재 등록 데이터에는 좌표·횡단 길이·현장 확인 정보가 부족하므로 실제 GPS 완료 확인은 해당 데이터 등록 후 가능합니다.
- GPS의 10초 초과 수신 공백과 6m/s 초과 순간 이동은 이동 거리에서 제외합니다. 뛴 횟수는 2m/s 이상이 3초 지속된 구간을 1회로 추정하고, 1.6m/s 미만이 2초 유지된 후 다시 뛰면 다음 회로 셉니다. GPS 오차로 실제 기록과 차이가 있을 수 있습니다.
- 가상 걷기: 접근 60m 후 초록 신호에서 횡단을 시작하고, 실제 길이가 없으면 시연용 20m를 더 이동한 뒤 자동 완료합니다. 결과에도 시뮬레이션 기록임을 표시합니다. 예전처럼 신호 타이머 종료만으로 성공 처리하지 않습니다.
- 확인 방법: `/crosswalk/main-gate?demo=1` → mock + 가상 걷기 → 속도 설정 → 패널 닫기 → 접근 및 횡단 완료 후 결과 확인.
- 완료 기록은 같은 탭의 `sessionStorage`에 저장해 새로고침 시 복원합니다. 좌표 이력은 저장하지 않습니다. 새 세션/재시작 시 이전 완료 기록을 지웁니다. 기록 없이 `/result`를 열면 안내 화면을 표시합니다.


## Vercel SPA 라우팅 및 배포 확인

루트 `vercel.json`은 페이지 요청을 `/index.html`로 내부 재작성해 React Router가 처리하도록 합니다.
`/api`, `/assets`, `/fonts` 경로는 제외합니다. API나 없는 정적 파일 요청에 HTML을 반환하지 않도록 하기 위한 설정입니다.
프로젝트 연결과 환경변수 등록은 Vercel 담당자가 진행하고, 이 설정이 포함된 브랜치를 배포합니다.

배포 완료 후 실제 배포 주소에서 다음을 확인합니다.

1. `/main`, `/crosswalk/main-gate`, `/crosswalk/main-gate?demo=1`, `/result`를 주소창에 직접 입력합니다.
2. 각 주소에서 새로고침했을 때 Vercel의 404 대신 앱 화면이 표시되는지 확인합니다. 완료 기록 없이 `/result`를 열면 기록 없음 안내가 정상입니다.
3. JS/CSS·폰트가 정상 로드되고, 존재하지 않는 `/api/...` 요청이 `index.html`로 바뀌지 않는지 확인합니다.

로컬 `vite` 개발 서버는 원래 SPA 새로고침을 지원하므로, 로컬 확인만으로 Vercel 재작성 설정을 검증할 수는 없습니다.
공식 가이드: https://vercel.com/docs/frameworks/frontend/vite

카카오 JavaScript SDK 배포 도메인 등록은 실제 주소 확정 후 진행합니다.
Kakao Developers → 앱 → 앱 설정 → 앱 → 플랫폼 키 → 사용 중인 JavaScript 키 → JavaScript SDK 도메인에서
`https://실제-배포-주소.vercel.app` 형태의 출처(프로토콜 + 호스트)를 추가하고 저장합니다.
`/main` 같은 경로는 붙이지 않으며, 사용하는 커스텀 도메인이 별도로 있다면 함께 등록합니다.
현재 메인 지도는 OpenFreeMap을 사용하므로 카카오 키의 도메인 등록 여부와 별도로 동작합니다.


## 지도 횡단보도·사과 표시

- OpenMapTiles의 기본 도로 타일에는 횡단보도 위치가 없어 별도 OSM 조회를 사용합니다. `highway=crossing` 노드와 `footway=crossing` 경로만 표시하며 일반 신호등 위치를 횡단보도로 만들지 않습니다.
- Overpass 공개 API를 조회하고 실패 시 다른 Overpass 제공자와 OSM API를 순서대로 사용합니다. 각 요청에 8초 제한을 두며 실패·빈 결과·재시도 안내를 표시합니다. API 응답과 원본 등록 상태에 따라 지역별 표시 개수가 달라집니다.
- 지도를 180m 이상 이동하면 조회를 갱신합니다. 700ms 대기 후 요청하고 이전 요청을 취소합니다. 같은 지역 결과는 5분간, 최대 20지역까지 메모리에 캐시합니다. 15레벨 미만으로 축소하면 마커를 숨겨 겹침을 줄입니다.
- 횡단 경로 중앙과 연결 도로 방향을 사용해 줄무늬를 배치합니다. 줄무늬는 화면용 심볼이며 실제 횡단 길이 측정값이 아닙니다.
- OSM 좌표가 있다고 실시간 신호를 알 수는 없습니다. 조회된 횡단보도는 `verified: false`, 신호는 `UNKNOWN`으로 표시하며, 빨강·초록은 임의로 만들지 않습니다. 등록된 검증 정보는 근접 중복 제거 시 우선합니다.
- 조회한 사과를 누르면 상세 안내로 이동하며, 상세 주소를 새로고침해도 OSM ID로 정보를 복원합니다. 신호 API 제어기 연결과 현장 확인 전에는 횡단 예측을 제공하지 않습니다.
- 지도 데이터 제공자 표시는 기존 지도 하단의 OpenStreetMap 크레딧을 따릅니다.


## 보행 속도 측정 · 걷기 안내 예측 (#8)

`src/features/strategy/`에 있으며, 일반 상세 화면(mock·live)과 데모(`?demo=1`)가 같은 로직을 사용합니다.

- `predict.ts`의 `decideGuide`: 신호·남은 시간·거리·횡단 길이·속도로 안내 상태를 판정합니다.
- `speed.ts`: GPS 위치 기록으로 보행 속도를 측정합니다.
- `guideCopy.ts`: 안내 카드 문구를 만듭니다.
- `PredictedGuide.tsx`: 실제 GPS와 함께 화면에 표시합니다.

보행 속도 측정

- 최근 10초 동안의 처음·마지막 위치 사이 직선 거리를 경과 시간으로 나눕니다. 제자리 GPS 흔들림이 누적되지 않도록 경로 합 대신 순이동을 사용합니다.
- 측정 구간이 3초 미만이면 측정 중으로 봅니다. GPS가 10초 넘게 끊기거나 6m/s를 넘게 튀면 그 지점부터 다시 잽니다. 위치 갱신이 멈추면 속도가 점점 줄어듭니다.
- 측정 중이거나 0.5m/s 미만(정지)이면 기본 속도 1.2m/s로 예측하고, 화면에 ‘기본 속도’로 표시합니다.
- 1.4m/s를 넘게 걸어도 예측에는 1.4m/s까지만 사용합니다.

안내 상태 판정. 필요 시간은 (남은 거리 + 횡단 길이) / 속도 + 여유 시간입니다.

| 신호 | 조건 | 안내 |
| --- | --- | --- |
| 정보 없음·끊김, 위치·횡단 길이·속도 없음 | | `NO_SIGNAL` (이유별 문구) |
| 초록 | 필요 시간 ≤ 남은 시간 | 도착 전 `GO_NOW`, 횡단보도 3m 이내 `CROSS_NOW` |
| 초록 | 1.4m/s 이하로 올리면 가능 | `GO_FASTER` (필요한 최소 속도 안내, 올림) |
| 초록 | 1.4m/s로도 부족 | `WAIT_NEXT` (뛰지 않기) |
| 점멸 | 항상 | `WAIT_NEXT` (새로 건너지 않기) |
| 빨강 | 빨간불이 끝나기 전에 도착 | `SLOW_DOWN` (남은 거리 / 남은 빨간불 시간, 내림. 0.5m/s 미만이면 앞에서 기다리기) |
| 빨강 | 도착 시점에 이미 초록 | `GO_NOW` (초록으로 바뀌면 다시 판정) |
| 빨강 | 횡단보도 3m 이내 | `WAIT_NEXT` |

- 여유 시간은 기본 3초이며, 지연된(10~30초 전) 정보는 3초를 더해 6초로 계산합니다. 30초 초과·끊김은 예측하지 않습니다.
- 서울 API로는 다음 초록불 길이를 알 수 없어, 빨간불 상태에서는 초록불 시작 시점에 맞추는 것까지만 안내합니다.
- `?state=`, `?status=` 주소는 피그마 화면 미리보기 전용이며 `src/data/mockGuides.ts`의 고정값을 보여줍니다. 그 외에는 항상 예측 결과를 표시합니다.
- 일반 상세 화면은 현장 확인(`verified: true`)과 좌표·횡단 길이 등록 후에 예측이 표시됩니다. mock 모드는 생성 신호(빨강 23초 → 초록 50초 → 점멸 6초)와 실제 GPS를 함께 사용하며 ‘데모 신호’로 표시합니다.
